# Translation (web app)

The web app speaks English (the source) and Russian, because many field crews read Russian more easily. The system is
small and dependency-free: `src/lib/i18n/`. The iOS app is not covered yet.

## The one rule about what is translated

**Only what a person on the team reads on screen is translated.** Everything that leaves the app stays in English:

- quotes, change orders, invoices, credit notes and payments as the client sees them (`ClientDocument`, `DocPdf`,
  `ChangeOrderPdf`, `/q`, `/d`, `/co`, `/p`, `/r` pages and every other client link);
- every PDF, CSV and export (estimate, sheets, daily log, photo report, as-built, task report, wiring sheets, labels);
- every email (client emails and team emails alike, for now) and the server's API replies (the app translates the
  known error messages where it shows them: `billing.ts`, `emailClient.ts`, `scan.ts` and `joinReply` /
  `accountDeleteReply` in `teamLogic.ts` pass the server's `error` through `t()`, and `ru/lib-strings.ts` has them);
- the legal pages (`/terms`, `/privacy`, `/legal/*`): the English text is the binding one. Links *to* them are
  translated.

Data people typed (job names, price list items, checklist templates, notes) is shown as typed: never pass it to `t()`.
Device letters on the plan are codes, not words: they stay as they are.

## API

```ts
import { useT, t, tn, msg, fmtDate, fmtNumber, fmtCurrency } from "@/lib/i18n";
import { T } from "@/lib/i18n/T";
```

| Where | Use |
|---|---|
| Client component | `const t = useT();` then `t("New job")`, `t("Hi {name}", { name })`, `t.tn("{n} device", "{n} devices", n)`. The component re-renders when the language changes. |
| Plain code (`src/lib`, event handlers, toasts) | `t(...)` / `tn(...)` from `@/lib/i18n`: they read the active language when called. Call them when the text is shown, not at module load (a module-level `const LABEL = t("…")` is frozen in English). |
| Text kept in data (nav arrays, option lists, `ROLE_INFO`-style tables) | Wrap the literal in `msg("Pricing")` (identity; lets the checker find it) and translate where shown: `t(item.label)` or `<T>{item.label}</T>`. |
| Server component / static page | Import `msg` from `@/lib/i18n/msg` and `T` from `@/lib/i18n/T` only (not `@/lib/i18n`: it pulls in React state). `<T>Plain English text</T>` is a small client island that renders English on the server and the visitor's language after hydration. For placeholders: `<T vars={{ name }}>{"Hi {name}"}</T>`. A page with a lot of text is simpler as a client component. |
| `metadata` / page titles | Stay English (server, SEO). |
| Dates, numbers, money | `fmtDate(d)`, `fmtTime(d)`, `fmtNumber(n)`, `fmtCurrency(n, company.currency)`. Follow the active language; currency never changes. Not for client-facing documents (they keep their own `en-US` formatting). In components, call `useT()` (or `useLocale()`) so they re-render. |
| Switch language | `<LanguageSwitcher />` (`src/components/LanguageSwitcher.tsx`), or `chooseLocale(locale)` from the same file. |

### Keys

- **The key is the exact English text** shown today. Changing the English text changes the key: update the Russian
  entry at the same time (the checker lists the new key as missing).
- Placeholders are `{name}` (letters, digits, `_`). The translation must use exactly the same set of placeholders
  (any order). Values are inserted as given: format numbers and dates first (`fmtNumber`, `fmtDate`).
- **Plurals**: never build plurals with `s` or `n === 1 ? … : …`. Use `tn(one, other, n, vars?)`; `{n}` is filled in.
  The Russian entry is keyed by the English **singular** and lists the forms:
  ```ts
  "{n} device": { one: "{n} устройство", few: "{n} устройства", many: "{n} устройств", other: "{n} устройства" },
  ```
  `one` = 1, 21, 31…; `few` = 2–4, 22–24…; `many` = 0, 5–20, 25–30…; `other` (optional) = fractions (falls back to
  `many`). `one`, `few` and `many` are required.
- Keep sentences whole: `t("Delete {name}?", { name })`, never `t("Delete") + " " + name + "?"` (Russian word order
  differs). Don't split a sentence around a link or `<strong>`; if you must, translate each piece as a phrase that
  stands on its own.
- `<T>` children must be one plain string (no `{expressions}` inside); whitespace and line breaks are collapsed.
- Missing translations fall back to English, so a half-translated screen still works.
- Dynamic keys (`t(ROLE_INFO[role].name)`, `t(err.message)`) work at runtime if the exact English text is in a
  dictionary; the checker can't see them, so prefer `msg()` at the source when you can edit it.

## Files: one per area

Russian lives in `src/lib/i18n/ru/<area>.ts`, merged by `src/lib/i18n/ru/index.ts`. Each area file only imports types
(`import type { Dictionary } from "../types";`) so the checker can load it. Translators working in parallel each own
one file:

| Area file | Covers |
|---|---|
| `site-auth.ts` | public site (`src/components/marketing`, `SiteFooter`, `/support`, `/pricing`), sign-in, sign-up, reset, `/join` |
| `shell-settings.ts` | app header, account menu, bottom bar, banners, update prompt, sync badge, `/settings` and its panels, team, billing, integrations settings |
| `plan-editor.ts` | `src/components/editor`, markups, measure, sheetIndex, revisions, progress, plan-side tasks UI |
| `field.ts` | `src/components/field`, photos, forms, checklists, tasks board, schedule, RFIs (team side) |
| `money-office.ts` | `src/components/money`, documents (team side), change orders (team side), estimate/pricing, price list, products, integrations' export |
| `job-views.ts` | jobs list and map, job header and tabs, Overview, Takeoff, wiring, job details, templates |
| `lib-strings.ts` | text produced in `src/lib` (labels, statuses, roles, errors, toasts) and shown via `t(value)` |

A key may appear in two areas only with the same translation (the checker fails otherwise). Common words ("Save",
"Cancel", "Delete") belong in the area of the file where you meet them first; if another area already has them,
don't add them again.

To add a language: add its code to `Locale` (`types.ts`) and `LOCALES` (`locales.ts`), create `src/lib/i18n/<code>/`
with the same area files and an `index.ts`, register it in `dictionaries.ts`, and teach `RU_PLURAL_FORMS` in the
checker its plural categories.

## Checking

`npm run check:i18n` (Node 22.18+, or the flags in `package.json`) reads every `t("…")`, `tn("…", "…")`, `msg("…")`
and `<T>…</T>` literal in `src/` and:

- **fails** on a translation whose placeholders differ from the English, `tn()` forms with different placeholders, a
  plural entry without `one` / `few` / `many`, an empty translation, or the same key translated differently in two
  areas;
- **warns** about English text with no Russian yet (`--all` lists every one);
- notes Russian keys it didn't find as literals (`--unused`; fine for dynamic keys).

`tests/i18n.test.ts` runs the same checks on the real dictionaries, plus the core (plurals, fallback, interpolation,
persistence).

## Choosing the language

- Per device: `localStorage["pinplan.lang"]`. With nothing saved, the browser's languages decide (`ru*` → Russian),
  else English.
- Per person: the switcher also saves `lang` in the signed-in account's metadata (`auth.updateUser({ data: { lang } })`).
  On a sign-in on any device the account's language is applied; on a reload it only fills in when the device has
  never chosen. An account without a language takes the device's choice.
- `<html lang>` follows the active language.
- The switcher (English / Русский, each in its own language) is in the account menu, the site header (menu on phones)
  and footer, and on the sign-in, sign-up, reset and join pages.
- Pages render in English on the server and switch right after loading (no hydration mismatch).

### Tone and typography

- Address the reader as **«вы»** (lower case), plain and short, like the English. Buttons and menu items use the
  infinitive («Сохранить», «Добавить объект»); instructions use the polite imperative («Введите код»).
- Write **ё** («Подсчёт», «Счёт», «Ещё»).
- Quotation marks «ёлочки»; the dash is « — » with spaces; numbers via `fmtNumber` (space for thousands, comma for
  decimals).
- Keep the product name, brand names (Billdu, Stripe, QuickBooks) and device letters in Latin.
- Russian is ~20–30% longer: check narrow places (phone bottom bar, tab labels, chips) and prefer the shorter synonym
  in the glossary over truncation.
